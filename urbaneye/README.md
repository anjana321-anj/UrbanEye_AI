# UrbanEye — See It. Report It. Fix It.

> *Every citizen can be the eyes of the city.*

UrbanEye is a smart-city civic reporting and municipal management platform built in **Flutter / Dart**.
One codebase contains two connected products:

| | Citizen app | Municipality Admin Console |
|---|---|---|
| Target | Mobile-first (390 × 844) | Desktop-first (1440 × 1024), responsive to tablet/phone |
| Who | Residents | Operators, team members, supervisors, administrators |
| Highlights | Animated splash, onboarding, permission agreement, AI-assisted 4-step report flow, duplicate detection, waste AI check, pickup + live truck tracking, city map with clustering, before/after confirmation, offline drafts, notifications, civic score | KPI dashboard, live map, report table + detail with validated status workflow, team assignment, SLA timers & auto-escalation, audit log, RBAC matrix, waste/truck operations, analytics |

Everything runs on a **mock backend** (Kathmandu sample data) behind clean repository interfaces, so you can demo it immediately and later plug in a real API without touching the UI.

## 2. Unzip the project

**Windows**
1. Right-click `UrbanEye.zip` → **Extract All…**
2. Choose a short path without spaces, e.g. `C:\dev\` → you get `C:\dev\urbaneye\`.
   (Short paths avoid Windows long-path build errors.)

**macOS**
1. Double-click `UrbanEye.zip` → a folder `urbaneye` appears.
2. Move it to e.g. `~/dev/urbaneye`.

**Linux**
```bash
unzip UrbanEye.zip -d ~/dev
```

## 3. One-time setup (generates the Android/Web platform files for *your* Flutter version)

The zip contains the app code, assets, launcher icons and the Android permission manifest.
The rest of the platform scaffolding (Gradle files, `MainActivity`, `web/`) is generated by your own Flutter installation so it always matches your version. Existing UrbanEye files are **not** overwritten.

**Windows** – double-click `setup_windows.bat`
(or run it from a terminal inside the `urbaneye` folder)

**macOS / Linux**
```bash
cd ~/dev/urbaneye
chmod +x setup_mac_linux.sh
./setup_mac_linux.sh
```

**Or run the two commands yourself** (any OS, inside the `urbaneye` folder):
```bash
flutter create --org com.urbaneye --project-name urbaneye --platforms=android,web .
flutter pub get
```

> If `flutter create` asks nothing and prints "All done!", it worked.

## 4. Open & run in Android Studio

1. **File → Open…** → select the `urbaneye` folder (the one containing `pubspec.yaml`).
2. If prompted, click **"Get dependencies"** / **"Pub get"**.
3. Start an emulator (**Device Manager → ▶**) or plug in a phone with USB debugging on.
4. Choose the device in the top toolbar and the run configuration **main.dart**.
5. Press **Run ▶** (or `Shift+F10`).

From a terminal instead:
```bash
flutter run                 # on the connected phone / emulator
flutter run -d chrome       # Admin Console in a desktop browser (best at 1440 px wide)
flutter build apk --release # installable APK in build/app/outputs/flutter-apk/
```

## 6. Permissions used (Android)

Declared in `android/app/src/main/AndroidManifest.xml` and requested at runtime only after the user accepts the in-app agreement:

| Permission | Why |
|---|---|
| `CAMERA` | Capture photo/video evidence and waste photos |
| `ACCESS_FINE_LOCATION`, `ACCESS_COARSE_LOCATION` | Pin the issue location, nearby issues, water points, truck ETA (only while the app is open) |
| `READ_MEDIA_IMAGES`, `READ_MEDIA_VIDEO` (`READ_EXTERNAL_STORAGE` ≤ Android 12) | Upload existing evidence from the gallery |
| `POST_NOTIFICATIONS` | Report and pickup status updates (Android 13+) |
| `RECORD_AUDIO` | Optional — only for video evidence with sound |
| `INTERNET`, `ACCESS_NETWORK_STATE` | Sending reports, map tiles, offline detection |
| `VIBRATE` | Haptic feedback |

Every permission can be denied: the app falls back gracefully (gallery instead of camera, manual map pin instead of GPS, etc.).

## 7. Project structure

```
lib/
├─ main.dart                 # bootstraps services, runs the app
├─ app.dart                  # providers, theme, i18n, RootGate (onboarding → consent → auth → citizen/admin)
├─ core/
│  ├─ config/env.dart        # --dart-define config (API URL, tiles, tenant) — no secrets in code
│  ├─ di/service_locator.dart# composition root: swap mock ↔ real repositories here
│  ├─ l10n/                  # English + Nepali (add languages by adding a map)
│  ├─ routing/routes.dart    # premium page transitions + navigation helpers
│  ├─ theme/                 # design tokens, light/dark/high-contrast themes, typography
│  └─ utils/utils.dart       # formatting, validation, motion (reduced-motion aware), haptics
├─ domain/
│  ├─ models/                # User, Report, Evidence, Team, Vehicle, WastePickup, AuditLog… + validated status machine + RBAC
│  └─ repositories/          # interfaces for auth, reports, notifications, teams, waste, analytics, locations, AI
├─ data/
│  ├─ api/api_client.dart    # REST contract for the production backend
│  ├─ mock/                  # in-memory backend seeded with Kathmandu data + mock AI
│  └─ services/              # permissions, GPS, connectivity, local storage, media capture/compression
├─ state/                    # ChangeNotifier controllers (auth, reports+offline queue, notifications, waste, admin, settings)
├─ widgets/                  # design-system components: buttons, cards, badges, timeline, charts, map abstraction, skeletons, states
└─ features/
   ├─ onboarding/            # splash, onboarding, permissions agreement
   ├─ auth/                  # login, sign-up, forgot password + OTP, staff login
   ├─ citizen/               # floating bottom navigation shell
   ├─ home/ report/ reports/ map/ waste/ notifications/ profile/ transparency/
   └─ admin/                 # console shell, dashboard, reports, teams, waste, analytics, SLA, audit, users, settings
```

### Connecting a real backend
1. Implement the interfaces in `lib/domain/repositories/repositories.dart` with HTTP calls (endpoints listed in `lib/data/api/api_client.dart`).
2. Construct them in `lib/core/di/service_locator.dart` when `USE_MOCK_BACKEND=false`.
3. Run with `flutter run --dart-define=USE_MOCK_BACKEND=false --dart-define=API_BASE_URL=https://your-api`.

No UI code needs to change.

## 8. Troubleshooting

| Problem | Fix |
|---|---|
| `The current Dart SDK version is …` / version solving failed | Update Flutter: `flutter upgrade`, then `flutter pub get` |
| `flutter create` didn't run / missing `android/app/build.gradle` | Run step 3 again from inside the `urbaneye` folder |
| Gradle / JDK errors | Android Studio → Settings → Build Tools → Gradle → Gradle JDK = *Embedded JDK (17+)*; then `flutter clean && flutter pub get` |
| Map is blank | Map tiles need internet. Check the emulator has network |
| Emulator camera shows a test scene | Normal — use **Upload Photo**, or set the emulator camera to *Webcam0* in AVD settings |
| Location shows Putalisadak / "Approximate location" | The emulator has no GPS fix — set one in Emulator → ⋯ → Location, or just drag the pin |
| `minSdkVersion` error from a plugin | In `android/app/build.gradle(.kts)` set `minSdk = 24` |
| Anything else | `flutter clean`, `flutter pub get`, run again. Copy the first red error line if you need help |
